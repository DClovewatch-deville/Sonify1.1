# MusicPhoto 三模式评估与改进记录

日期：2026-10-14。新入口：`http://127.0.0.1:8766/studio.html`。旧 `lab-v3.html` 保留。

## 原版本评估

已有价值：六张真实线稿的骨架数据、图形谱、启发式结构候选、声部规则、SoundFont 乐器、MIDI 导出及三模式实验材料已经存在。不是从零开始。

主要不足：

1. Blueprint 有约八千至一万二千个密集椭圆，形状可辨，但像点描，音乐符号的组织与留白不足。
2. 页面将六个样本和大量试听全部纵向排列，像实验报告，窄屏横向溢出，无法形成一个作品的完整体验。
3. Progressive 使用多段独立试听，缺少统一音频时钟、连续章节和真正随播放变化的作品画面。
4. 旧分类把“高位横线”等候选直接解释成屋顶、神庙等物体，证据不足；边框也可能被当成屋顶。
5. 旧轮廓旋律只取得首点；source_point 缺失；音符 ID 使用进程随机化 hash；部分移调跳出声称的五声音阶。
6. 旧并发检查只检查起音时刻，不能证明整个音符持续区间的预算。

## 本轮实现

### 产品层

新增独立 Geometry Studio，复用原始提取数据，不覆盖旧实验逻辑。用户选择一张作品，然后在 Blueprint / Soul / Progressive 之间切换。

- 墨绿、象牙白、金色的统一界面；桌面作品与规则面板并排，窄屏上下排列。
- Blueprint 使用原骨架采样的空间疏化、源路径连线、符头和切向相关符干；保持源图宽高比例。
- Soul 展示五声部时间对齐草谱，点击符号或选择事件可以回查来源。
- Progressive 是 36 秒、六个章节的连续作品。背景按总进度渐显；真实正在发声的源路径额外彩色高亮。明确区分这两种动画。
- 页面内本地 SoundFont 分轨播放；暂停、继续、停止、章节跳转、进度条、声部静音；停止或切换模式会终止当前音源。
- Blueprint 共用 Soul 的音乐骨架，装饰性图形音符不全部发声。界面明确说明。
- 规则面板显示来源路径、实际插值采样坐标、计算公式、中间音阶索引、MIDI 音高、起音、时值、音色和稳定 ID。
- 保留 MIDI 和完整规则 JSON 下载。

### Sonic Grammar 的具体实践

`studio_grammar.py` 是新规则实现；`grammar.py` 旧实验保持原样。

1. 几何词汇：高位长线、竖向结构、水平支撑、细节短线、轮廓走势。沿用 `primitives.classify`，排除靠图像上下边界且跨图宽 65% 以上的横向边框候选。没有长柱时，从短竖线补充最多五个候选。不声称是语义识别。
2. 非轮廓路径取弧长中点；轮廓取沿路径弧长等距四点。每个点都位于真实源线段上。
3. 普通高度映射：d=13(1-y)，四舍五入并夹取索引 0..13。
4. 轮廓映射：d=13(1-center)+4(center-y)/max(0.12,span)。局部升降成为旋律升降，而非只使用第一点。
5. 固定音阶 MIDI=[48,50,52,55,57,60,62,64,67,69,72,74,76,79]。支撑声部下移五个音阶位置并夹取到边界，保证仍在音阶内。
6. 声部及音色：高位长线→电钢琴；竖向→弦乐；支撑→大提琴；细节→音乐盒；轮廓→长笛。GM program 为零基编号 4/48/42/10/73。
7. 时值分别 1.5/.45/2.5/.25/.42 秒；按六秒章节组织。高位长线重复三次，支撑两次；其他类别选取代表路径，轮廓构成四音动机。章节轮换源路径，避免永远播放相同一个局部。
8. 事件区间扫线检查最多四个同时持续的音符；同声部同音高不得重叠。发生冲突时按 .25 秒后移，超出章节则舍弃。乐器释放与混响尾音不属于该事件预算。
9. SHA-256 派生事件 ID，数据含 source/source_point/rule/calculation/chapter。固定输入与规则得到固定输出。
10. 渐显逐章加入声部；已有声部每章重新进入。静音仅改变该音轨 Gain，不重排剩余音符，支持消融展示。

### 视觉与声音的边界

所有保留图形符头来自密集骨架数据；音乐事件来自稀疏代表性路径。两者共用同一张源图，但不是每个图形符头一一对应一个声音。点击图形画面选择最近的音乐采样事件，面板显示其真实来源。不得把此交互描述为所有装饰点都已进入音乐。

Soul 草谱使用时间横坐标和音高纵坐标，还没有传统谱号、小节、连音与符尾的严格制谱语义。Blueprint 的连线来自源路径，不代表经过乐理排版的连音线。当前仍需更多人工审美迭代，不能宣称已达到参考猫形艺术曲谱的完成度。

## 验证

- 全部 unittest：40 项通过（旧管线与新 studio 合计）；最后音轨幅度检查后重跑新 studio 三项通过。
- 六张样本 × 两模式检查来源存在、采样点位于原线段、稳定 ID、固定输入确定性、音阶约束、音符区间并发、音轨采样率与时长。
- 检查轮廓产生多个采样点与不同音高、Progressive 每章仅使用已加入的层。
- 发现旧渲染器把每条声部独立归一化至约 .7，直接相加会超满幅。新版浏览器每声部 Gain=.25；五声部最坏峰值总和不超过 .875，保留混音余量。
- 浏览器实际验证三模式往返、Blueprint/Soul/Progressive 播放、章节跳转；窄屏与 1280px 桌面检查。浏览器能够加载本地音轨且时间轴推进。未将“播放成功”等同于人工音乐审美验收。

## 构建与运行

源文件：`ui/studio.html`、`ui/studio.css`、`ui/studio.js`、`studio_grammar.py`、`build_studio.py`。

依赖在 `requirements.txt` 增加 tinysoundfont==0.3.7。需本地 `dist/soundfonts/FluidR3Mono_GM.sf3` 与既有六份 sample JSON / blueprint JSON。

在 experiment 目录执行：

```powershell
python build_studio.py
python -m unittest discover -p 'test*.py'
python -m http.server 8766 --bind 127.0.0.1 --directory dist
```

本机已有服务，不必重复启动。build_studio 重新生成 studio 数据、60 条本地声部 WAV、MIDI 和界面。旧 v3 构建源码中加入新版入口，避免重建后丢失链接。
