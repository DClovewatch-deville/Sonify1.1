# MusicPhoto 渐进式生成旅程

依据：GPT_Advice/图转线稿/对话3.docx，以及当前真实产物和批量测试。

## 产品主线

收件台负责管理图片，单张旅程负责观看体验。批量导入或手机上传，都进入同一收件台；选择一张后，以原图为主画面，其余作品退回可收起的列表。每张图片独立保留原图、边缘图、几何、音乐及播放入口。新上传不能自动切走正在观看的图片。

OpenCV 不承诺“理解了主体”，也不等于原图结构真值。它确定性地检测亮度边缘，阴影、字幕、纹理仍可能参与计算；路径分类与选材是当前的几何启发式。AI 继续作为可选审美增强，不阻塞核心演示。

## 节奏与数据依据

| 阶段 | 观看节奏 | 必须使用的真实数据 | 避免的误导 |
| --- | --- | --- | --- |
| Capture | 原图停留约 2 秒 | 当前 job 的 original.png | 不切成内置示例 |
| Dissolve | 约 2 秒褪色、淡出 | 同源原图和处理结果，保留比例 | 褪色是解释转场，不是声称 OpenCV 分步推理 |
| Draw | 约 7 秒路径逐段显现 | 完整音乐路径图 contours[].points | 不用随机线条、不用横向遮罩冒充路径描绘 |
| Geometry | 约 3 秒少量真实来源高亮 | notes[].source → contours[].id | 不把端点包装成已识别角点、交叉点或语义对象 |
| Translate | 约 5 秒，最多三个例子 | 实际来源、MIDI 音高、声部、作品时间和音轨片段 | 不新增无来源音符或用随机音乐替代 |
| Perform | 淡出引导，进入完整作品 | 当前 job 的私有 manifest、谱面、分轨音频 | 不跳到共享 sample 样例 |

所有持续时间是可调观看节奏，不是算法耗时。后台快于动画时，允许重绘已完成结果，并明确是“观看生成过程”；后台未完成时，用真实阶段状态等待。跳过、暂停、重播应始终可用；跳过不提前声称作品已经准备完成。

## 本轮独立可运行预览

新增 /journey?job=<id>，批量作品用 /journey?batch=<batch>&job=<id>。

这是一段约 20 秒的独立原型：原图 → 褪色 → 完整路径逐段绘制 → 真实来源路径/端点 → 最多三个声部片段 → 进入现有三模式作品页。支持暂停、重播和跳过。用户点击开始时解锁音频，片段来自现有 Soul 比赛版实际分轨；片段可能同时包含该声部的其他音符，不宣称是孤立单音。

描绘顺序目前是长路径优先、同长度按空间位置排序，不具备“屋顶 → 窗户”语义规划。骨架路径与栅格边缘图也不是逐像素等价，最后转场明确回到边缘图，不声称所有原始细节都已成为音符。

批量索引提供此预览入口。为避免干扰正在开发的 Soul，本轮不改主线 UI；进入三个模式仍打开独立作品页，尚未实现整个主线在同一组件内无缝接续。

## 后续集成优先级

1. 将收件台“打开作品”接到旅程，再进入三模式；保留“直接进入作品”给熟练演示者。
2. 同页承载作品区，并定义离开时声音、动画和资源的统一清理；主线模块稳定后再接，不通过复制随机 UI 状态模拟衔接。
3. 路径描绘改为层内并行、层间推进：基于真实长度、方向和空间分组，仍使用“主导长轮廓/重复候选/支撑候选”等诚实名称。
4. 在实际音符采样点上呈现音高、时值与节奏，再交给现有 Soul 诞生动画，避免重复解释两遍。
5. 结合不同图像的测试记录控制展示密度；碎线密集时只演示代表路径，再淡入完整线稿。保留剩余路径用于核查，不能为了动画清爽偷偷更换音乐输入。

## 审美与验证边界

动画应保持同一张图、同一视觉中心、同一色彩声部分工。避免每一步切一张卡片，让观众重新寻找对应关系。预览通过代码/浏览器验证，只证明交互与数据一致；画笔节奏和音乐审美仍需要用户观看试听确认。

批量成功率、边缘密度和路径数不能代替音乐质量评分。不同图片可能被同一乐章模板和音阶约束成相近音乐，需要另外比较主题走势、声部进入和实际来源选材。这是下一阶段算法工作，不能通过漂亮动画掩盖。
