# 专用本地结构线稿工作流：需要用户介入的准备

## 本轮判断

22 张原图已对比当前 Canny、保边平滑加碎块过滤、降低处理尺度加碎块过滤。后两者能减少部分碎线，但在风景和弱对比度图像上仍出现主体漏失；无法仅凭线条数量减少认定主次更明确。结合用户提供的模型线稿，建议把图生图模型作为高质量结构线稿的下一步接入路径。本结论针对当前测试，不宣称已经穷尽传统计算机视觉方法。

## 现在需要准备什么

目前在台式机上开发。不要修改或占用原有 8190 工作台。需要用户创建/启动黑客松专用实例，例如 8191（实际端口可不同），确认模型和自定义节点在此实例可用，然后在 GUI 中用一张本轮原图跑通结构简化。

最小链路：LoadImage → 原有可用图生图/图像编辑工作流 → 解码/必要后处理 → SaveImage。

交给程序的材料：

1. 专用实例地址；若仍与本服务在台式机运行，可用回环地址。未来若笔记本负责界面、台式机负责推理，需要另外验证两机可达，不能把台式机的 localhost 填到笔记本。
2. **API 格式** workflow JSON，不是只有界面位置/连线的编辑器 JSON。
3. LoadImage 输入节点 ID，以及最终 SaveImage 输出节点 ID。
4. 当前准确模型、分辨率、步数、种子和一张成功结果；用于确认既有效果、又可以重复运行的基准。

密钥不需要发到聊天中，本地 ComfyUI 方案也不需要购买云 API。豆包仍可作为另一个待开通适配器，但本轮没有付费调用，没有假定其延迟一定比本地短。

## 输出要求

- 原图长宽比与构图尽量保持，避免人为装饰边框、字幕、水印和阴影排线；主要轮廓清楚，避免把树冠变成大量孤立叶片。
- 不添加物体或主要边界；不要为了画面丰富而补细节。这个要求需检查实际结果，不能靠提示词就认定保真。
- 返回单张完整 PNG，使用指定保存节点取结果，避免拿到中间预览。
- 保留现有优质工作流的提示词和参数作为基准。线条很淡时，后端可规范化对比度，再做几何解析；不应再次用 Canny 将每条细线变成双边缘。
- 如果模型改变尺寸/构图，音乐来源坐标绑定到模型线稿；原图到线稿只做对照转场，不将模型坐标冒充精准对应原图。

## 接入配置

intake/config.local.json 的 comfy_url、comfy_workflow、comfy_input_node、comfy_output_node。已有适配器负责上传图片、替换输入、提交工作流、轮询历史、获取指定输出。8190 端口受到拒绝检查。

本地模型的请求仅在专用配置完成后使用；本轮未读取/启动现有 8190，也未安装或替换用户模型。

## 一分钟等待如何处理

不假设有排队观众，也不通过固定长动画伪装模型进度。

第一步记录冷启动、预热后推理和传输耗时，确认真正瓶颈。随后在同源图片上测试当前模型允许的较低分辨率/较少步数；是否可用要以结果判断，不能保证能将一分钟压到几秒。

产品允许用户主动选择“快速结构”或“精简线稿”，显示各自真实状态。若高质量路径仍需一分钟，必须如实提示；快速路径可提供可选即时体验，但不自动替换正在播放的版本。正式描线/音乐映射动画只在对应数据已就绪后开始，可跳过和重播。

本次材料准备齐后，下一步由 Codex 完成真实联调、耗时测量、同源效果对比和最终默认路径调整。
